**Libell 1.5.1** — a patch release that makes the automatic update work. Since 1.4.0 – CR729 a new version was downloaded but then waited until the app was closed completely and started again, so an app that was only opened or brought back kept showing the old version. Now the new version takes over at once and the app reloads into it.

Open it at **https://libell.app/** — to pick up this fix, close the app completely and start it once more. From then on it updates itself.

## Highlights

- **The update really happens by itself.** When a new version is out, the app reloads into it on its own: when you start it, when you bring it back to the screen (and once more half a minute later, in case the connection was not up yet), every ten minutes while it stays open, and when you tap the name and version in the top bar. You no longer need to restart it.

## Under the hood

- The cause was a build setting: since the worker began loading after the first render (1.5.0's faster start), the build tool no longer told a new version to take over at once. Both settings are now set explicitly.
- The smoke test now starts the built app, publishes a changed version underneath it and checks that the open page reloads into it. Without the fix it fails.
- 2726 unit tests, as in 1.5.0.

## Honest limitations

- This one time, the fix itself only arrives after a full restart, because the version you have still waits for one.
- The app reloads straight away, also in the middle of levelling or with a sensor box connected; reconnecting a box after that may open the device list again.
- Everything listed under 1.5.0's limitations still applies.
